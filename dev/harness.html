Overstudy widget & its clusters

The single busiest surface, and the one most worth redesigning: four independent modules append to one row. Shown as the user really meets it in the browse state, then module by module.

Everything at once — browse state, mistakes logged, lines queued

Overstudy (2) + auto-play (3) + mistakes (2) + continuation (3) = ten controls in four groups, read left to right as mistakes → practice → session → settings. Exactly one is filled: Review queued lines, named by reviewRowPrimary().

Press the status text to cycle through the real messages — the buttons above must not move.

The primary, state by state (§3.1)

One rule, evaluated in one place. Two of these states have no filled control at all, which is the answer to "what next?" when there is nothing to do.

Browse, mistakes only → Retry.

Browse, lines available → Review clickables; Retry drops back to an outline.

Live quiz → none. Retry is visible, refuses if pressed (v0.57.0), and must not also be the loudest thing under the board.

Browse, nothing pending → none. The mistake group is gone and took its separator with it.

Auto-play — a cog in the row, settings behind it

The cog carries the state the hidden toggle used to show, in colour and in its tooltip. Never a fill: it is a setting, and a fill means "the one thing to do next".

Overstudy — one button, and the chooser it raises

Two buttons for one intention, the second dead for the whole first variation of every session. Now the choice is asked for only when there is one; with a single variation to offer, the press goes straight there.

Collapsed mid-quiz (§3.3)

Default while a quiz is live; the label toggles it and the choice is dropped when the state flips. Only things actively running survive — and they survive because of gates the modules already set, not a new flag.

Quiz live, nothing running → the label alone.

Type a move (section 22)

Off by default. The only control in this row that acts on the card being answered, so it sits first after the label — and it is the third exception to the mid-quiz collapse, for the same reason the other two are: mid-quiz is when it has something to do. An input, not an action, so it takes none of §3.2's five treatments; it looks like the field it is, and goes green at the border when the keyboard is going to it.

Quiz live, waiting for a move. Everything else is collapsed away; the field is what is left.

⌨ Enter plays O-O — or keep typing for O-O-O

The one case that needs Enter, and the status line that says so. Status text never shares a line with a control (§F8).

⌨ No legal move here starts like that

Nothing legal starts like that: the border goes red, the text stays legible — the user is mid-word and about to fix it.

⌨ Enter goes to the next variation

Browse state (v0.65.1): the field STAYS, empty and inert, because hiding it closes a phone's keyboard and every variation would then cost a tap before the first move could be typed. It takes no moves here — Chessable's post-completion board accepts none — so the one key it answers is Enter, which asks the trainer for the next variation. Everything else falls through to MoveTrainer's own shortcuts.

It is NOT the row primary: Retry still is. A text field cannot be, and a field that never claims to be the thing to press is exactly why it can sit here through both states without competing.

The status line shows ONLY while the field holds the keyboard — measured here, it costs the browse row 26px (38 → 64), and the Lichess panel anchors below this widget. Remove the .clo-tm-status above to see the unfocused browse row.

Show and grade (section 23)

Off by default, and /practice/ only. The second control in this row that acts on the card being answered, so it sits beside the move field — and the FOURTH exception to the mid-quiz collapse, for the same reason as the other three: mid-quiz is the only time it has anything to do. Idle it is an ordinary action (green outline, §3.2); running, it becomes Stop and takes the row primary, because a mode that owns the whole session must not make its exit a hunt.

Browse state, mode idle. It is NOT the primary here — Retry is. Offering to start a study mode is not louder than the outstanding mistakes.

Quiz live, mode RUNNING, auto-play OFF. Everything else collapses away; Stop is what is left, and it is filled. The exception matches on the button carrying .clo-rowprimary — the module's own "I am running" state, so there is no extra flag to keep in step.

Auto-play ON. The toggle carries its own state — accent on the border and the text, never a fill: a fill in this row means "the one thing to do next", and this is a preference. It only shows while the mode is running, which is the only time it means anything. Section 23's auto-play is separate from section 13's and neither toggle touches the other.

👁 Promotions have to be played on the board

The one refusal the mode can hand back mid-card. Amber text on the row's own status line, like every other status here (§3.2) — never inline among the controls.

Show and grade — the board ring (section 23)

In the real thing this board wears Chessable's own board image, copied off the live page, so it follows whichever theme the user has picked. The checkerboard below stands in for it. The ring is 4px amber plus a 1px dark edge: at 2px it sat on a busy green border and read as part of the board rather than as a frame. Thicker rather than a new colour, because the colour carries meaning — amber is "this board takes no input", against the green of the drill and the line quiz, which do.

Left to right: your card — the arrow is up, and it means the board has stopped and is waiting for you to grade, not "this is the move" (the piece and the two tinted squares already said that). Then the same card auto-played: no arrow, because it grades itself a beat later and there is no decision to point at. Then your card over a light theme. Then the quiz board for comparison — green ring, our own squares, and it takes moves.

The arrow is the ring's amber, read off --clo-attention rather than repeated in JS: one colour, one idea — "waiting for you". It was the quiz board's green until v0.77.0, which on Chessable's own green board image had the same lack of edge that made the 2px ring unreadable.

Show and grade — the replay-speed popover (section 23)

Behind the cog, because both are persistent preferences and everything else in this row acts on the session in front of you (DESIGN-ui-inventory §F4). Body-mounted and fixed in the real thing — inside the row it would change the widget's height, which the Lichess panel, the alt-check chip and the heads-up all anchor below. Pace is the beat before each move is shown; animation is how long a piece takes to slide, and the advance beat is floored at it so the two cannot be set against each other into one blurred move.

In a blindfold build the board is not drawn and this prompt is what announce() speaks.
